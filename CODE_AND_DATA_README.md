# Real-Time Rideshare Event Analytics on GCP — Starter Code and Data

> **Important: sample data is synthetic for demonstration only.**
> The original project summary (Sep–Dec 2023, Pub/Sub / Dataflow / Beam /
> BigQuery / Streamlit / Python, 10K events/min, 40% BigQuery cost cut,
> anomaly alerts within 60 seconds) is the project context, not a claim
> about this starter code. This repo does **not** reproduce the original
> 10K/min production throughput or cost savings, and Pub/Sub / Dataflow /
> Beam / BigQuery are shown here as architecture and SQL examples only —
> **not a live GCP deployment**.

## What each file does

| File | What it does |
| --- | --- |
| `data/sample_events.csv` | 2,000 synthetic rideshare events, generated by `src/generate_events.py`. Columns: `event_id`, `event_time`, `city`, `event_type`, `driver_id`, `rider_id`, `fare_amount`, `trip_minutes`. Cities: New York, San Francisco, Chicago, Austin. Event types: `ride_request`, `ride_completed`, `ride_cancelled`, `driver_online`. Includes 10 deliberate duplicate `event_id` rows to test deduplication. |
| `src/generate_events.py` | Generates `data/sample_events.csv` deterministically (seed 42). Re-run it any time to regenerate the same file. |
| `src/stream_processor.py` | Pandas simulation of the streaming logic: deduplicates by `event_id` (exactly-once simulation), buckets events into 5-minute tumbling windows by city and event type, computes event count and average fare per window, and flags demand-spike anomalies where a window's count exceeds the rolling mean + 2 × std of the previous 12 windows for that city/event type. Writes `outputs/windowed_counts.csv` and `outputs/anomalies.csv`, and prints input / deduped / window / anomaly counts. |
| `sql/bigquery_schema.sql` | BigQuery table DDL for the events, partitioned by `event_date` and clustered by `city`, `event_type`, with comments explaining the cost-optimisation (partition pruning, clustering, selecting only needed columns). Replace `your-project.rideshare.ride_events` with your own project/dataset before use. |
| `dashboard/app.py` | Streamlit app. Reads `data/sample_events.csv` and, if present, `outputs/windowed_counts.csv` / `outputs/anomalies.csv`. Shows events by city, events over time, events by type, windowed counts, and the anomaly alerts table. |
| `analysis/run_analysis.py` | Offline analysis with pandas + matplotlib only. Reads `data/sample_events.csv` and writes charts to `outputs/charts/`: `events_by_city.png`, `events_by_type.png`, `events_over_time.png`. |
| `requirements.txt` | `pandas`, `matplotlib`, `streamlit`. |

## How to run

From the project root:

```bash
pip install -r requirements.txt

# 1. Generate the synthetic sample data (deterministic, seed 42)
python3 src/generate_events.py

# 2. Run the streaming simulation (dedup + 5-minute windows + anomalies)
python3 src/stream_processor.py

# 3. Run the offline analysis (charts)
python3 analysis/run_analysis.py

# 4. Run the Streamlit dashboard
streamlit run dashboard/app.py
```

Outputs:

- `outputs/windowed_counts.csv` — one row per 5-minute window / city / event type.
- `outputs/anomalies.csv` — only the windows flagged as demand spikes (header only if none are flagged).
- `outputs/charts/events_by_city.png`, `events_by_type.png`, `events_over_time.png`.

## Notes

- `fare_amount` and `trip_minutes` are 0 for `ride_cancelled` and
  `driver_online` events, where no trip fare / trip duration applies.
- The 10 duplicate rows are exact copies of the first 10 generated events,
  appended at the end of the CSV, so the file has 2,000 rows but 1,990
  unique `event_id` values. The stream processor must report 10 duplicates
  removed.
- To turn this starter into a real pipeline, you would replace the CSV
  input with Pub/Sub, the pandas windowing with Dataflow/Beam, the local
  outputs with BigQuery (see `sql/bigquery_schema.sql`), and the local
  Streamlit demo with a deployed app — none of that is wired up here.
